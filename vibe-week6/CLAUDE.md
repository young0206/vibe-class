# 프로젝트 헌법

## 행동 원칙

### Think Before Coding
불확실한 내용을 추측하지 않는다. 필요한 질문을 하거나, 진행에 필요한 가정을 명시한다.

### Simplicity First
요구사항을 충족하는 최소한만 구현한다. 미래를 위한 추상화와 과설계를 피한다.

### Surgical Changes
요청 범위 밖의 코드·주석·파일을 건드리지 않는다. 기존 스타일과 동작을 보존한다.

### Goal-Driven
작업마다 검증 방법을 먼저 정한다. 변경 후 관련 테스트와 `npm test`로 결과를 확인한다.

## 프로젝트 규칙

- 환경: 외부 의존성 없는 간단한 Node.js 프로젝트
- 전체 테스트: `npm test`
- 개별 테스트: `node --test test/<파일명>.test.js`
- 구조: 테스트는 `test/` 아래에 `*.test.js`로 둔다.
- 기능 변경에는 재현 가능한 테스트를 함께 추가한다.

## 금지사항

- 요청과 무관한 리팩터링이나 포맷 변경을 하지 않는다.
- 비밀키, 토큰, 개인정보를 코드·문서·로그에 남기지 않는다.
- 오류나 실패한 검증 결과를 숨기지 않는다.

세부 원칙은 @GOLDEN_RULES.md를 따른다.
