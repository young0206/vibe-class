# Golden Rules

1. 단순하게 유지한다. 필요한 만큼만 구현한다.
2. 기존 동작을 먼저 이해하고 변경한다.
3. 사용자 요청과 직접 관련 없는 파일은 수정하지 않는다.
4. 기능 변경에는 재현 가능한 테스트를 추가한다.
5. 오류를 숨기지 않고 원인과 해결 방법을 명확히 남긴다.
6. 비밀키, 토큰, 개인정보를 코드나 로그에 포함하지 않는다.
7. 완료 전에 전체 테스트를 실행하고 결과를 확인한다.

## Why

- 외부 패키지 없이 Node.js 내장 기능만 사용해 설치 단계와 환경 차이 없이 실습을 재현한다.
- 검증 명령을 `npm test` 하나로 고정해 사람과 에이전트가 같은 완료 기준을 사용한다.

## Gotcha

- 테스트는 `test/*.test.js`에 둔다. 다른 위치나 이름은 `node --test`의 자동 탐색에서 누락될 수 있다.
- `report-week6.md`의 체크박스나 빈 기록은 완료 증거가 아니다. 실제 산출물과 테스트 결과를 확인한 뒤 갱신한다.
- `package.json`의 Node.js `>=20` 조건을 확인하고, 더 낮은 버전에서의 성공을 보장하지 않는다.
