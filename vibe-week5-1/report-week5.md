# 5주차 Agent-Ready 도입 전/후 비교

## 질문
이 프로젝트에 "메뉴 카테고리 필터" 기능을 추가하고 싶어.
어느 파일을 수정해야 하고, 메뉴 데이터는 어디에 추가해야 하며,
디자인은 어떤 방식으로 맞추고, 수정 후 무엇을 확인해야 하는지
계획만 말해줘. 코드는 아직 수정하지 마.

## 도입 전
현재 구조에서는 세 파일만 수정하면 됩니다. 아직 코드는 변경하지 않았습니다.

  1. 메뉴 데이터 구조 변경 — script.js:1

  - 기존 문자열 배열 koreanMenus를 카테고리를 포함하는 형태로 변경합니다.
  - 예: { name: "김치찌개", category: "찌개" }
  - 새로운 메뉴도 이 배열에 추가합니다.
  - 초기 카테고리는 실제 메뉴 구성을 기준으로 전체, 찌개, 밥, 면, 고기, 분식 정
    도로 나눌 수 있습니다.

  - 필터 선택 상태를 관리하고, 선택된 카테고리에 해당하는 메뉴 안에서만 무작위
    추천하도록 로직을 수정합니다.

  - 필터 결과가 없을 때를 대비한 예외 처리도 넣습니다.

  2. 카테고리 선택 UI 추가 — index.html:16

  - 설명과 추천 결과 영역 사이에 카테고리 필터를 배치합니다.
  - 여러 개의 버튼을 하나의 그룹으로 묶고, 기본값은 전체로 설정합니다.
  - 현재 선택된 필터를 시각적으로 표시하면서 aria-pressed 같은 접근성 상태도 함
    께 제공합니다.

  - 기존 추천 버튼과 구분할 수 있도록 별도의 클래스명을 사용합니다.

  3. 기존 디자인에 맞춘 스타일 추가 — style.css:1

  - 현재의 크림색 배경, 주황색 강조색, 둥근 모서리를 그대로 사용합니다.
  - 카테고리는 큰 추천 버튼보다 작은 칩 형태로 디자인합니다.
  - 선택 상태에는 기존 추천 버튼의 주황색을 사용하고, 미선택 상태에는 연한 배경
    과 테두리를 적용합니다.

  - 기존 전역 button 규칙이 필터 버튼에도 그대로 적용되지 않도록 추천 버튼과 필
    터 버튼의 스타일 범위를 분리합니다.

  - 좁은 화면에서는 필터가 자연스럽게 여러 줄로 배치되도록 flex-wrap을 사용합니
    다.

  - 키보드 포커스, hover, active 상태도 기존 스타일과 통일합니다.

  4. 수정 후 확인할 항목

  - 첫 화면에서 전체가 기본 선택되는지
  - 각 카테고리를 누르면 선택 표시가 정확히 하나만 남는지
  - 추천 결과가 선택한 카테고리 안에서만 나오는지
  - 전체에서는 모든 메뉴가 추천 대상인지
  - 카테고리를 바꾼 뒤 추천 버튼을 여러 번 눌러도 오류가 없는지
  - 키보드의 Tab과 Enter/Space로 필터를 조작할 수 있는지
  - 결과 영역의 aria-live 안내가 계속 정상 작동하는지
  - 모바일 너비에서 필터와 카드가 잘리거나 넘치지 않는지
  - 브라우저 콘솔에 JavaScript 오류가 없는지

  현재 프로젝트에는 자동화된 테스트나 빌드 설정이 없으므로, 구현 후에는 브라우저
  에서 기능·접근성·반응형 동작을 직접 확인하는 방식이 적절합니다.

## 도입 후
수정 계획은 다음과 같습니다. 아직 코드는 변경하지 않습니다.

  - index.html
      - 메뉴 추천 영역에 카테고리 필터 UI를 추가합니다.
      - 버튼 또는 선택 요소에 적절한 레이블과 접근성 속성을 적용합니다.

  - script.js
      - 기존 koreanMenus 배열의 메뉴 항목에 카테고리 정보를 추가합니다.
      - 새 메뉴 데이터가 필요하면 반드시 이 배열에만 추가합니다.
      - 선택된 카테고리에 맞춰 추천 후보를 필터링한 뒤 기존 추천 동작을 이어가도
        록 수정합니다.

      - 전체 카테고리, 빈 결과, 반복 클릭 같은 상황도 처리합니다.

  - style.css
      - 필터의 모든 스타일은 인라인 없이 이 파일에 작성합니다.
      - 기존 주황·크림 색상, 둥근 카드와 버튼 형태를 유지합니다.
      - 선택 상태와 키보드 포커스가 명확히 보이도록 하고, 모바일에서는 버튼이 잘
        리거나 화면 밖으로 넘치지 않게 반응형으로 구성합니다.

  수정 후에는 브라우저에서 다음을 확인합니다.

  - 각 카테고리 선택 시 해당 메뉴만 추천되는지
  - 전체 카테고리에서 기존 추천 기능이 그대로 동작하는지
  - 추천 버튼을 여러 번 눌러도 정상 동작하는지
  - 카테고리 변경 후 추천 상태가 자연스럽게 갱신되는지
  - 키보드 조작과 접근성 속성이 유지되는지
  - 콘솔 오류가 없는지
  - 모바일 화면에서 필터와 결과가 잘리거나 넘치지 않는지

## 관찰
도입 전 답변은 세 파일의 수정 위치와 구현 세부사항까지 제시했고, 도입 후 답변은 `index.html`, `script.js`, `style.css`별 책임을 더 간결하게 구분했다. 두 답변 모두 수정할 파일과 역할은 명확하지만, 도입 전 답변이 배치 위치, 버튼 그룹, 스타일 범위 등에서 더 구체적이다.

메뉴 데이터 위치는 두 답변 모두 기존 `koreanMenus` 배열이라고 밝혔다. 특히 도입 후 답변은 새 메뉴 데이터를 “반드시 이 배열에만 추가”한다고 표현하여 데이터 추가 위치에 관한 규칙을 더 명확하게 강조했다.

두 답변 모두 기존 크림색·주황색과 둥근 형태를 유지한다고 설명한다. 도입 후 답변에는 인라인 스타일을 사용하지 않는다는 규칙이 명시되었지만, 외부 라이브러리를 추가하지 않는다는 규칙은 어느 실제 답변에도 직접 제시되지 않았다.

검증 항목은 두 답변 모두 카테고리별 추천, 전체 추천, 반복 클릭, 키보드 접근성, 콘솔 오류, 모바일 넘침을 다룬다. 도입 전 답변은 기본 선택 상태, 단일 선택 표시, Enter/Space 조작, `aria-live` 동작까지 명시하여 수정 후 검증 내용을 더 구체적으로 제시했다.
